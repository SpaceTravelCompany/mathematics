# 각 장 반복 항법·보일러플레이트 제거

## 목표

페이지마다 기계적으로 반복되는 항법·템플릿 텍스트를 전량 제거한다. 내용을 담은 문장은 남긴다.

1. **항법 블록쿼트** — 75개 파일 6번째 줄:
   ```
   > 학습 순서 N / 75 · [처음부터 읽기](math-language.html)
   ```
2. **장별 라벨** — 첫 섹션(`## ` 헤딩과 그다음 `## ` 사이)에서 문장 앞에 붙은 템플릿 라벨만 제거하고 문장은 일반 문단으로 남긴다. 총 146건, 4종:
   - `**앞에서 가져올 것:** ` 73건 (73개 파일 각 1회)
   - `**증명으로 이어 읽기:** ` 42건
   - `**본문으로 이어 읽기:** ` 30건
   - `**확률로 이어 읽기:** ` 1건 (`counting.md`)
   - 뒤의 셋은 같은 "… 이어 읽기" 템플릿의 변형이므로 일관되게 함께 처리한다(사용자 확정).
   - 두 파일(`math-language.md` 등)에는 이 라벨이 없다.
3. **하단 이전/다음 항법** — 75개 파일 끝의 블록(테마 구분선 `---` + 빈 줄 + 링크 줄 3줄):
   ```
   [← 이전: …](….html) · [다음: … →](….html)
   ```

4. **파편 문장 6건** — 2번 라벨을 떼면 명사구 파편이 되는 첫 문단 6개에 한해 머리말을 붙여 완결 문장으로 만든다(S9, 사용자 승인).

비대상:
- `content/sets-and-logic.md`의 실제 내용 블록쿼트(`> **참고:** $\oplus$ …`) — 본문 내용이다.
- 2번 라벨 **뒤의 문장** — 사용자 결정에 따라 보존한다(라벨만 제거).
- 섹션 사이를 가르는 중간 `---` 구분자 — 하단 항법에 딸린 마지막 `---`만 제거한다.

근거:
- 순서 정보(학습 순서 N / 75)는 `site.json`의 `sections[].topics[]` 배열이 원천이므로 이 줄을 지워도 순서 데이터는 남는다. 생성기(`node_modules/topic-pages`)에는 이 문구를 만드는 코드가 없다(grep 0건) — 즉 마크다운에 손으로 박힌 텍스트다.
- 두 라벨은 **줄 단독으로 존재하지 않는다**(실측: 단독 0건). 전부 `라벨 + 공백 1칸 + 실제 문장` 형태이므로 줄 전체를 지우면 103개 문단의 내용이 유실된다. 그 이유로 라벨만 제거한다.
- 하단 항법은 각 파일 마지막 내용 줄이며, 바로 위 2줄이 정확히 빈 줄과 `---`다(실측 75/75). 링크 형태는 이전+다음 73개, 이전만 1개(`causal-inference.md`), 다음만 1개(`math-language.md`)다.

## 단계

### S1 — 드라이런으로 대상 확정

제거 정규식은 ASCII만으로 앵커한다: 줄 시작 `>` + 같은 줄에 `](math-language.html)` + 뒤따르는 빈 줄.

- 검증: `changed 75 / skipped 0` 보고. 추가로 제거 대상 줄이 전부 100자 미만이고 `**`를 포함하지 않음을 단언(실제 본문 블록쿼트 오식별 방지).

### S2 — 적용

드라이런과 동일한 정규식으로 실제 쓰기. 줄바꿈은 정규식이 매치한 바이트만 지우므로 CRLF/LF 혼재가 있어도 다른 줄은 바뀌지 않는다.

- 검증: 재드라이런 시 `changed 0`.

### S3 — 무손상 검증 (git diff가 증거)

작업 시작 시점 작업 트리는 clean이므로 diff가 곧 이번 변경 전량이다.

- 검증: `git diff --numstat`가 75개 파일 각각 `0	2`(= 추가 0줄, 삭제 2줄), `git diff --shortstat`가 `75 files changed, 150 deletions(-)`.
  추가 0줄이면 파일 내 다른 문자가 **한 바이트도** 바뀌지 않았다는 뜻이다(한글 재타이핑 손상 위험 자체가 없음).
- 검증: `Select-String -Path content\*.md -Pattern '학습 순서'` 결과 0건.

### S4 — 빌드 및 산출물 검증

- 검증: `npm run build` 종료 코드 0, `dist/topics/*.html` 75개.
- 검증: `dist` 전체에서 `처음부터 읽기` 0건, `학습 순서` 0건.
- 검증: `dist` 전체의 리터럴 `**` 개수가 변경 전과 동일(10건) — 렌더링 회귀 0.

### S5 — 문서 갱신

- `docs/ai/KNOWN_ISSUES.md`에 이번 변경이 만든 잔여 항목이 있으면 반영.
- 발견한 재사용 가능 패턴이 있으면 `~/.dsh/docs/ai/solutions/`에 기록.

### S6 — 장별 라벨 제거(문장 보존)

첫 섹션 안에서 줄 시작 `**…:** ` 형태를 ASCII 패턴(`/^\*\*.{1,60}:\*\* /`)으로 찾아 라벨 + 뒤 공백 1칸만 지운다. 한글 리터럴을 스크립트에 넣지 않기 위함이다.

- 가드: 코퍼스 전체 매치 수가 정확히 146, 서로 다른 라벨이 정확히 4종이고 건수가 73·42·30·1이어야 한다. 하나라도 어긋나면 **쓰기 없이 중단**한다. 제거 후 줄이 공백으로 시작하지 않아야 한다.
- 범위 가드: 첫 `## ` 헤딩부터 그다음 `## ` 전까지로만 매치를 제한한다. 전체 파일에서 이 패턴은 HEAD 기준 1807건이라 전역 스윕은 오식별한다(첫 섹션 밖은 `**예제 N (…):**` 같은 정상 라벨).
- 검증: `git diff --numstat`의 추가·삭제가 각각 라벨 제거분 146. 라벨 2개를 가진 73개 파일은 앞 블록쿼트 제거분 `0	2`에 `2	2`가 더해져 `2	4`가 된다.
- 검증: `Select-String '앞에서 가져올 것'`·`'이어 읽기'` → 각 0건. 제거 로그의 라벨 잔여 문장이 제거 전후 동일.

### S7 — 하단 이전/다음 항법 제거

각 파일 끝의 `\n---\n\n[<링크 줄>]\n`을 지운다. 이 매치는 앞의 빈 줄까지 포함하므로 실제로는 **4줄**(빈 줄 + `---` + 빈 줄 + 링크 줄)이 사라진다.

- 가드: 파일이 `\n---\n\n[<링크 줄>]\n`로 끝나야 한다(링크 줄이 마지막 내용 줄, 그 위가 빈 줄, 그 위가 `---`). 조건이 어긋난 파일은 skip하고 보고한다(중간 `---` 구분자를 잘못 지우지 않기 위함). 매치 수가 75여야 한다. 치환 결과가 정확히 trailing newline 1개로 끝나야 한다.
- 검증: `git diff --numstat`의 삭제가 하단 항법분 300(= 75 × 4) 추가, 추가 0줄.
- 검증: `Select-String '← 이전'`·`'다음:'` → 0건. 각 파일의 `---` 개수가 HEAD보다 정확히 1개 적다.

### S8 — 전체 재검증

- 검증: `git diff --shortstat` = `75 files changed, 146 insertions(+), 596 deletions(-)`(150 + 146 + 300).
- 검증: **변경 줄 전량 분류** — `git diff -U0`의 삭제 596줄이 빈 줄 225 + `---` 75 + 항법 블록쿼트 75 + 하단 링크 75 + 라벨 146으로만 구성되고 `OTHER` 0건. 추가 146줄은 각각 대응하는 삭제 라벨 줄에서 라벨 접두만 뗀 것과 **텍스트가 정확히 일치**(파일별 짝 검사). 이 두 조건이면 본문 문장이 하나도 사라지지 않았다는 뜻이다.
- 검증: `npm run build` 종료 코드 0, 75 페이지. `dist` 전체에서 제거 문구(항법·라벨·이전/다음) 0건.
- 검증: `dist/topics/*.html` 리터럴 `**` 개수가 10건 유지(렌더링 회귀 0), `<h2>` 없는 페이지 0개, 각 페이지 본문 첫 요소가 `<section>`+`<h2>`, 기사 끝에 `<hr>` 잔재 0건.
- 검증: 하단 항법 제거 후에도 페이지 간 이동 경로가 남아 있는지 — 사이드바 75개 페이지 전부와 `dist/index.html`이 `math-language.html`을 계속 링크한다.
- 검증: content 전체에 CR 바이트 0건(줄바꿈 무변경), 75개 파일 전부 frontmatter 4줄 + 빈 줄 + `## ` 헤딩 구조 유지.

### S9 — 파편 문장 6건 정리

라벨 제거로 첫 문단이 명사구 파편이 된 6개 파일의 문장에 머리말 한 조각을 붙여 완결 문장으로 만든다(사용자 승인). 다른 67개 파일의 전제 문장은 그대로 둔다.

- 검증: 6개 파일에서 수정한 줄이 정확히 1줄씩이고, 나머지 문장 텍스트가 접두 추가 외에 달라지지 않았다(변경 줄 전량 분류의 재작성 짝 검사).
- 검증: 각 수정 파일을 read-back해 한글이 손상되지 않았음을 확인(비ASCII 쓰기 검증 규칙).

### S10 — `sets-and-logic.md` 첫 문단 다시 다듬기

S9에서 붙인 머리말이 "…의 원소 기호와 ‘모든 경우’라는 말에서 출발한다"여서, 무엇을 가리키는지 이름만으로는 잡히지 않는다는 지적(사용자). `math-language.md`의 기호표가 실제로 무엇을 정의했는지 확인해 구체적으로 다시 쓴다.

- 근거: `math-language.md` 43행 `$x\in A$` = "$x$가 모임 $A$에 들어 있다", 46행 `$\forall$` = "모든 경우에". 이 장의 직관적 설명도 ‘모든’, ‘어떤’ 같은 양화사의 범위를 강조한다.
- 검증: 수정 후 read-back으로 한글·수식 무손상 확인. 빌드 후 `dist/topics/sets-and-logic.html`에서 문단이 정상 `<p>`로 렌더되고 링크 `math-language.html`이 살아 있는지 확인.
- 검증: 변경 줄 전량 분류 재실행 — 재작성 줄이 여전히 6개 파일에만 있고 그 외 파일에 미짝 추가 줄 0건.
